| ボタン | 押すと | 出る場面 |
| --- | --- | --- |
| 🎲 シャッフル | `settings.mediaShuffle` を反転（オンで色が付く＝`aria-pressed="true"`） | バーが出ているとき |
| 🔁 リピート | `settings.mediaRepeat` を **なし → 1曲 → 全曲 → なし** と回す（1曲のときは 🔂） | 同上 |

- どれも**独自の状態を持ちません**。🎲🔁 は既存の `core.settings.mediaShuffle`／`mediaRepeat`（再生画面が使っている値）そのものです。
- 変えると `core.emit("mediaOptions")` で再生画面へ知らせ、再生画面側で変えたときも同じ合図でバーが描き直します（**新しい保存キーは増えていません**）。

### 2.1 シャッフルのときの ⏮⏭

| シャッフル | ⏮⏭ の選び方 |
| --- | --- |
| オフ（既定） | これまでどおり、一覧の前後の曲（`library.nextSong()`／`prevSong()`） |
| オン | 一覧（`library.allSongs()`）から**いまの曲を除いて**1曲を選ぶ。1曲しか無ければその曲 |

純粋関数 `shufflePick(list, currentKey, random)` を `Trk.playerBar` から読めます（テストで乱数の位置まで固定して確かめています）。

### 2.2 試聴（ライブラリ）の曲の終わり

リピートが **1曲** のときは、試聴が終わると**曲の頭から**鳴らし直します（それ以外は、これまでどおり試聴の開始位置へ戻る）。
`previewRestartFor(repeat, start)` を `js/library.js` から出してあり、`Trk.library.previewRestartFor` で読めます。

## 3. 設定

| 設定 | 値 | 既定 | 効くところ |
| --- | --- | --- | --- |
| `playerBarSeekLock`（バーに触れても位置を移動しない） | オン / オフ | **オフ** | バーの位置の線を触ったときに位置を動かすか（❓謎設定。⚙ → ❓） |

- **新しい保存キーは、この1つだけ**です（trk225 までは0個）。`?reset=all`（工場出荷状態）でも既定（オフ）へ戻します。
- 4言語（日本語・英語・中国語・韓国語）。❓謎設定の欄は `#playerBarSeekLock`。
- **既定は「触れれば動く」**です。相談の「今のままがいい人」は、この設定をオンにしてください（`js/ui-prefs.js` の `DEFAULT_ON` には入れていません＝オンにはなりません）。

### 3.1 触れない状態になる条件（`seekEnabled`）

```
触れる ＝ 謎設定がオフ かつ 読み込み済み かつ 長さが分かっている かつ 画面が ライブラリ／プレイ中／一時停止
```

- リザルト画面・未読み込み・長さ0（配信の待ちなど）では触れません（これまでと同じ）。
- 触れないときは、線の上でカーソルが `default` に戻り、`.is-locked` が付きます。謎設定が理由のときは、触ると「バーは『触れても位置を移動しない』設定です（⚙ → ❓ 謎設定）」と案内します。

### 3.2 どこを動かすか

| 画面 | 動かす先 |
| --- | --- |
| ライブラリ（試聴中） | 映像（`core.video.currentTime`）を直接。試聴の一時停止状態はそのまま |
| プレイ中・一時停止 | `Trk.play.seekTo(秒)`（ゲームの進行に任せる＝これまでと同じ道） |

## 4. ⧉ 別窓の操作パネル（相談4）

### 4.1 調べたこと（実装前）

| 方式 | 事実 | 採否 |
| --- | --- | --- |
| **Document Picture-in-Picture**（`documentPictureInPicture.requestWindow()`） | 任意の HTML を**常に手前**の小窓に出せる。**Chrome／Edge 116+、Firefox 151+。Safari は未対応**、Android の Chrome／Firefox も未対応。**https（secure context）とユーザー操作**が要る。1タブ1窓。**位置はサイトから指定できない**。CSS は写す必要がある。`pagehide` で片付ける | **第一**に採用 |
| `window.open` の小窓 | どこでも動くが、常に手前にはならない。ブラウザのポップアップ制限に掛かることがある | **予備**に採用 |
| 画中絵（PiP の映像だけ） | trk は映像（動画）ではなく、曲名・操作を出したい | 不採用 |

参考：Chrome の Document PiP の解説（`developer.chrome.com/docs/web-platform/document-picture-in-picture`）、MDN の要約。

### 4.2 作ったもの（`js/player-panel.js`・新規）

- **出る条件**：`panelAllowed({desktop, pip, popup})`＝**PC型**（`body.trk-mobile` が付いていない）で、Document PiP か小窓のどちらかが使えるとき。**スマホ型では ⧉ を出しません**（端末では Document PiP が使えず、下部ナビとも競合するため）。
- **窓の大きさ**：560×216（横長。画像2の並びに合わせました）。
- **中身**：上段＝ジャケット・曲名・歌手／中段＝位置の線／下段＝⏮ ▶ ⏭ 🎲 🔁・経過と長さ・音量・✕。
- **鏡方式**：**DOM は移しません**。`Trk.playerBar.snapshot()`（曲名・時間・比率・再生中・シャッフル・リピート・音量・触れるか）を 250ms ごとに読み、`paintParts()` で絵だけ更新します。操作は `Trk.playerBar` の関数（`playPause`／`step`／`shuffle`／`repeat`／`seekToRatio`／`setVolume`）を呼ぶので、**バーと同じ道**を通ります。
- **スキン**：`getComputedStyle` から `--ui-*` を写して `:root{…}` を窓に差し込みます（写せないときは既定色）。外部への通信はしません（オフラインで動きます）。
- **片付け**：窓の `pagehide` と本体の `pagehide` で閉じます。スマホ型へ切り替えたら閉じます。閉じたらバーの ⧉ の `aria-pressed` を戻します。
- 窓口：`Trk.playerPanel = { available, open, close, isOpen, kind, pipUsable, popupUsable, panelAllowed, buildPanel, paintParts, skinVars, varsCss }`。

1. **位置の線を触った感じ**：ライブラリの試聴中に線を押す・なぞると、その位置へ動くか（曲が飛びすぎたり、つまんだりしないか）。
2. **❓謎設定をオン**にして、線を触っても動かないこと。触ったときに案内が出ること（出すぎないこと）。
3. **🎲 と 🔁**：バーで押すと、**メディアプレイヤーの画面のボタンも**同じ状態になるか（逆も）。シャッフル中に ⏭ を押して、毎回違う曲になるか。リピート1曲で曲が終わると頭から鳴るか。
4. **⧉**（PC型で）：
   - Chrome／Edge で押すと、**常に手前の小窓**が出るか（Document PiP）。
   - Safari／Firefox で押すと、**別の小窓**が出るか（Document PiP が無いときの予備）。ポップアップがブロックされないか。
   - 小窓の**曲名・時間・ボタンが読めるか**、**スキンの色**に合っているか。
   - 小窓の ▶ で本体が再生されるか。小窓を閉じたあと、バーの ⧉ の色が戻るか。
   - **スマホ型に切り替える**と ⧉ が消え、開いていた小窓も閉じるか。
5. **狭い幅**（430px 以下）：🎲🔁⧉ が増えたぶん、ジャケットが消えて詰まるか。ボタンが折り返さないか。

## 7. 事実と推測

- **事実**：§5 の数値はすべてこのセッションで実行した結果です。**実ブラウザ・実機は未確認**（この作業環境にブラウザも端末もありません）。
- **事実**：Document PiP の対応状況（Chrome／Edge 116+、Firefox 151+、Safari 非対応、モバイル非対応、https とユーザー操作が要る）は、実装前に調べたものです。**この環境では実際の窓を開いてはいません**。
- **推測**：`window.open` の小窓は、ブラウザのポップアップ設定によっては開かないことがあります（押した直後に開くので、たいていは許されます）。
- **推測**：Document PiP の窓の**位置はブラウザが決めます**（サイトから指定できません）。「画面の右下に出したい」といった指定はできません。
