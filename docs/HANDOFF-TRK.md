# trk（上流）引き継ぎ（2026-10-30）

> この文書は、上流 `trk` と配布用 `trk-Standalone` の関係を整理するためのメモです。上流リポジトリで作業するエージェントは、まずこれを読んでください。

## 1. 位置づけ

- **上流 `TonbokiriRaikiriMuramasa-Taikoubou/trk`**：trk! の本体。ブラウザで動く音ゲー＋プレイヤー。オフライン駆動性を高めてきた現行プロジェクト。
- **`trk-PWA`**：上流1.1.8を履歴ごと取り込んだ、iPhone配布用の作業リポジトリ。現在の公開準備地。
- **`trk-Standalone`**：iPhoneホーム画面から使う standalone PWA の新しい家（予定）。上流のコード＋モバイルシェル＋iOS調整を持つ。
- **`trk-apk`**：Android APK版の別系統。iOSとは配布形態が違う。

**上流は「アプリの機能と品質」のsource of truth。** 配布用リポジトリは、上流の変更を取り込みながら、iPhone向けのシェルと設定を重ねる。

## 3. 上流に置くもの／置かないもの

### 上流に置いてよいもの

- ゲーム本体のバグ修正、性能改善、アクセシビリティ、i18n。
- どの環境でも嬉しいUI改善。
- オフライン／保存まわりの共通改善。
- セキュリティ修正、依存更新。
- ドキュメントのうち、製品全体に共通するもの。

### 上流に置かないもの（配布用リポジトリ側）

- iPhone専用のモバイルシェル（画面幅・タッチ・セーフエリアの調整）。
- `apple-touch-icon`、iOS用のインストール案内、`navigator.audioSession` などiOS固有の設定。
- GitHub Pages の配布ワークフロー、公開URL、配布用README。
- 独自ドメイン／組織名に依存する設定。
- 「0円で不特定多数に配る」ための案内文。

※ モバイル向けの改善が**どの環境でも自然に効く**なら、上流に還元してよい。判断は所有者に確認する。

## 4. 同期の手順

配布用リポジトリで上流の更新を取り込む：

```sh
git remote add upstream https://github.com/TonbokiriRaikiriMuramasa-Taikoubou/trk.git
git fetch upstream
git merge upstream/main
# 競合を解消
npm ci
npm run check
```

- 競合は「上流の機能」を優先し、その上にモバイルシェルを載せ直す。
- コアのJS（`js/`）を配布用だけで大きく書き換えない。シェルは別ファイル／別CSSに寄せる。
- 上流の履歴を配布用リポジトリに持ち込む場合も、上流のコミットを書き換えない。
- 上流へ還元するときは、配布用の差分から**一般化できる部分だけ**を抽出し、別PRにする。

## 5. ライセンスとクレジット

- 上流・配布用とも **GPL-3.0-or-later**。`LICENSE` を保持する。
- 曲・効果音・フォント・vendorライブラリのクレジットを消さない（`credits.html` / `docs/`）。
- 配布用リポジトリのREADMEに、上流との関係とライセンスを明記する。
- ストア規約とGPLの非互換があるため、App Store配布はしない（方針として確定済み）。

## 6. エージェントの方針

- 上流の `main` へ直接pushしない。変更はPR。
- `main` のforce push、履歴の書き換えをしない。
- 上流のPages設定・公開URLを勝手に変えない。
- 変更後に `npm ci`、`npm run check` を通す。
- 実機で見ていないことを「確認済み」と書かない。
- 費用・Secrets・ストア登録が必要なら相談する。
- 配布用リポジトリの都合（組織名、URL、アイコン）を上流に持ち込まない。
- 上流のIssue/PRと配布用のIssue/PRを混ぜない。アプリ本体の不具合は上流、配布・iPhone固有は配布用。

## 7. やってはいけないこと

- 上流リポジトリの名前変更（`trk` は既に使われているURL・参照がある）。
- 上流のPagesを配布用サイトで上書きすること。
- 上流の履歴をsquashして配布用に取り込むこと（同期が壊れる）。
- GPLの著作権表示・ソース公開を外すこと。
- 配布用の独自ドメイン／組織名を上流の設定に埋め込むこと。
