# 下の再生バーの置き場所と「隠さない」（trk225・2026-10-31）

> **対象**：**trk225**（trk223／trk224 の次）／PR #6
> **きっかけ**：PC の実機をスマホ型で使ったときの相談（スクリーンショット2枚つき）。
> **この文書の立ち位置**：直したこと・確かめたこと・**まだ実機で見ていないこと**を分けて書きます。期待と違ったら、それが不具合です。

---

## 1. 何が気になっていたか（相談の内容）

| # | 気になっていたこと | どうしたか |
| --- | --- | --- |
| A | スマホ型では、下の**操作パネル（ライブラリ・エフェクト・再生・書斎・ゲーム）**が画面のいちばん下にあり、**曲の再生バーがその上**に載る。バーが画面の途中に浮いているように見えて、UX として違和感がある | **置き場所を選べる設定**を足した。既定は「**画面のいちばん下**（操作パネルはバーの上）」 |
| B | 再生時間をいつも出しておきたい人が、バーの **✕** を誤って押すと消えてしまう | **「再生バーを隠さない（✕ を出さない）」** を足した（既定オフ） |

## 2. 設定（⚙ → 🖥 画面と再生バー）

| 設定 | 値 | 既定 | 効くところ |
| --- | --- | --- | --- |
| `playerBarPos`（バーの置き場所） | `bottom` / `above` | **`bottom`** | **スマホ型**のときの、バーと下部ナビの前後 |
| `playerBarLock`（再生バーを隠さない） | オン / オフ | オフ | バーの ✕ を出すか（オフ＝これまでどおり ✕ が出る） |

- 保存は既存の `core.settings` だけ（**新しい保存キーは増やしていません**）。`?reset=all`（工場出荷状態）でも既定へ戻します。
- 4言語（日本語・英語・中国語・韓国語）。

### 2.1 置き場所の2つ

```
bottom（既定）                      above（trk221〜trk224 までと同じ）
┌──────────────────────────┐        ┌──────────────────────────┐
│  画面（曲リスト・設定など）    │        │  画面（曲リスト・設定など）    │
│                          │        │                          │
├──────────────────────────┤        ├──────────────────────────┤
│ 操作パネル（ライブラリ…）      │        │ 曲のバー                    │
├──────────────────────────┤        ├──────────────────────────┤
│ 曲のバー                    │        │ 操作パネル（ライブラリ…）      │
└──────────────────────────┘        └──────────────────────────┘
```

- **PC型**は下部ナビが無いので、どちらを選んでも同じ（画面のいちばん下）です。
- バーが出ていないとき（表示しない・プレイ中・再生画面・書斎）は、下部ナビは元の位置（いちばん下）へ戻ります。

### 2.2 「隠さない」の範囲

| 操作 | オン（隠さない）のとき | オフ（既定）のとき |
| --- | --- | --- |
| バーの ✕ | **ボタンを出さない**（押せないボタンより、無いほうが迷わない） | 押すと「表示しない」になって保存される |
| 設定の「下に出す再生バー → 表示しない」 | **そのまま使える**（本人が選ぶ操作なので止めない） | 同じ |

「誤って消す」を防ぐのが目的なので、止めるのは ✕ だけにしました。設定から自分で「表示しない」を選んだ場合は、その選択を尊重します。

## 3. 仕組み（あとから読む人向け）

- **バーの下余白は JS**：`js/player-bar.js` の `measure()` が `barPos()`（`bottom`／`above`）を見て、`--trk-playerbar-offset` に `0px`（bottom）またはナビの高さ（above）を入れます。同時に `body.trk-playerbar-at-bottom` を付け外しします。
- **ナビを動かすのは CSS**：`css/player-bar.css` の
  `body.trk-playerbar.trk-playerbar-at-bottom .trk-mobile-nav { bottom: var(--trk-playerbar-h) }`。
  `--trk-playerbar-h` は**実寸**（`getBoundingClientRect`）なので、拡大率（`zoom`）がかかっていても段が重なりません。
- **safe-area**：いちばん下に来るバー自身が `padding-bottom: calc(9px + env(safe-area-inset-bottom))` を空けます。ナビは「バーの実寸ぶん上」なので、safe-area を足し直しません（二重に空けない）。
- **✕ の非表示**：`.trk-pb-actions button { display: grid }` が `[hidden]`（ブラウザ既定の `display:none`）に勝ってしまうため、`.trk-pb-actions button[hidden] { display: none !important }` を足しました。
- 純粋関数：`barOffset(navHeight, position)`（`above` のときだけナビの高さを返す）、`barPos()`（知らない値は `bottom`）、`barLocked()`。どれも `window.Trk.playerBar` から読めます。

## 4. 確かめたこと（自動検査）

`npm run check` = **896 pass / 0 fail**（trk224 の 874 から 22件）。うち trk225 は `tests/trk225-player-bar-settings.test.mjs` の 22件です。

- 判定：`offset(66.4, "above") = 66`、`offset(66.4, "bottom") = 0`、位置を省いたときは `0`（重ならない側）。未設定・知らない値は `bottom`。
- 実測（偽 DOM）：既定で `--trk-playerbar-offset = 0px`・`--trk-playerbar-h = 60px`・`body.trk-playerbar-at-bottom` が付く。「ナビの上」に変えると `66px` になり、印が外れる。**設定を変えた瞬間に測り直す**。バーを出さない場面では印も外す。
- 隠さない：オンで ✕ が `hidden`、✕ を押しても `playerBar=auto` のまま・保存 0 回・案内 1 回（`barLocked`）。オフなら従来どおり `off` になって保存される。設定の欄で切り替えるとその場で消える／戻る。
- CSS を規則として当てた値：ナビの `bottom` が `var(--trk-playerbar-h, 56px)`（bottom）／`0`（above）。`[hidden]` の ✕ は `display:none !important`。カードの下余白 `100px + 56px = 156px` は、バー 56 ＋ ナビ 66 = 122px より広い。
  （この3つは、直す前の CSS なら `0` / `grid` になり落ちることを確かめてあります＝検査が空回りしていません。）
- 文言：7つのキーが4言語ぶんあること。設定の欄（`#playerBarPos`・`#playerBarLock`）が `index.html` にあること。

## 5. まだ確かめていないこと（実機で見てほしい）

1. **スマホ型・既定**（PC のブラウザでも、右上の 📱 でスマホ型にできます）：画面のいちばん下が**曲のバー**、その上が**操作パネル**になっているか。バーが画面の途中に浮いていないか。
2. **設定で「操作パネルの上」に切り替え**ると、trk224 までの見た目に戻るか（開き直さずに変わるか）。
3. **拡大率 125%** のとき、バーと操作パネルの段が重なったり、すき間が空いたりしないか（バーの実寸で測っていますが、`zoom` の効き方はブラウザ差があります）。
4. **iPhone（Safari／ホーム画面アプリ）**：いちばん下のバーがホームバー（画面下の横線）に隠れないか。操作パネルがその上に来るか。
5. **「隠さない」オン**：バーから ✕ が消えるか。✕ が無いことで困らないか（設定からは「表示しない」にできます）。
6. **「隠さない」オフ**：これまでどおり ✕ が出て、押すと消えるか。

気になったら「端末・OS・ブラウザ・拡大率・スキン名・どの設定か」を添えて教えてください。

## 6. 事実と推測

- **事実**：§4 の数値はすべてこのセッションで実行した結果です。実ブラウザ・実機は**未確認**（この作業環境にブラウザも端末もありません）。
- **推測**：`zoom` のかかったバーの実寸と、`env(safe-area-inset-bottom)` の入り方は、ブラウザによって差が出る可能性があります。実機で違ったら、`--trk-playerbar-h` の測り方を変えます。
